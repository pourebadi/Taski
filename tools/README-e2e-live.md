# اجرای تست سناریوهای واقعی روی سایت زنده

این اسکریپت همان کاری را می‌کند که خواسته بودید: **واقعاً** به سایت وصل
می‌شود، لاگین می‌کند، پروژه و کاربر و کار می‌سازد، همه‌ی گذارهای وضعیت و
سناریوها را می‌زند، و هر جا سرور رفتار غلط نشان دهد گزارش می‌دهد.

هیچ وابستگی‌ای ندارد. فقط Node نسخه ۱۸ یا بالاتر لازم است.

## اجرا

```bash
# اول همیشه این را بزنید — فقط می‌خواند، چیزی نمی‌سازد
node tools/e2e-live.mjs --read-only

# اجرای کامل
node tools/e2e-live.mjs

# با آدرس یا حساب دیگر
node tools/e2e-live.mjs --base=https://your-server.example.com --username=admin --password=...
```

## ⚠ قبل از اجرای کامل بخوانید

این محصول **هیچ مسیر حذفی ندارد**. کار فقط «لغو» می‌شود، پاک نمی‌شود.
پروژه، تیم و کاربر هم اصلاً حذف نمی‌شوند. یعنی هر چیزی که این اسکریپت
بسازد، در دیتابیس شما می‌ماند.

برای همین همه‌ی ساخته‌ها با پیشوند `[E2E]` علامت می‌خورند تا در رابط
کاربری بتوانید پیدایشان کنید. اگر روی دیتابیس اصلی تیم اجرا می‌کنید:

1. اول `npm run backup:now` بزنید
2. بعد با `--read-only` امتحان کنید
3. تازه بعد اجرای کامل

یا بهتر: یک نمونه‌ی جدا بالا بیاورید و روی آن اجرا کنید.

## چه چیزهایی را می‌زند

۱۲ گروه سناریو، حدود ۹۰ بررسی:

| گروه | چه می‌کند |
|---|---|
| سلامت و احراز هویت | health، ورود درست و غلط، رفرش بدون کوکی، توکن نامعتبر، نشت وجود حساب |
| اعتبارسنجی ورودی | ۱۲ ورودی بی‌معنا به پروژه، کاربر و کار — هیچ‌کدام نباید ۵۰۰ بدهد |
| ساخت دنیا | ۲ پروژه، ۱ تیم، ۵ کاربر با نقش‌های مختلف، کلید و نام‌کاربری تکراری |
| ساخت کار | ۸ کار با ترکیب‌های مختلف بازبینی/تست/اولویت/پروژه، یکتایی کلیدها، سلسله‌مراتب دو سطحی |
| ماشین حالت | مسیر خوشحال، بازگشایی، گذارهای غیرمجاز، دور زدن بازبینی از راه QA، لغو بدون علت |
| تعهد | اولین ETA، چند بار عقب رفتن، تاریخ بی‌معنا، پیوستگی نسخه‌ها، تغییرناپذیری Baseline اول |
| تغییرات ردیابی‌شده | اولویت/مهلت/مجری/مالک بدون علت، پاک کردن مهلت، تغییر بی‌ضرر |
| سلامت و دیدگاه | توضیح اجباری، استقلال دو محور، دیدگاه خالی، نرمال‌سازی «ک/ك» در جست‌وجو |
| فیلترها و آمار | ۱۴ مسیر، و بررسی اینکه فیلتر واقعاً فیلتر می‌کند |
| دسترسی‌ها | ورود واقعی با حساب مشاهده‌گر و تلاش برای کارهای ممنوع |
| نگهبان‌های مدیریتی | غیرفعال کردن خود، تنزل نقش خود، واگذاری، بازنشانی رمز |
| قرارداد خطا | قالب خطا، نشت stack trace، هدر x-request-id، نشت هش رمز |

## خواندن خروجی

- `✓` سبز — درست کار می‌کند
- `✗ باگ` قرمز — رفتار غلط تأییدشده، با توضیح اینکه چه انتظار می‌رفت
- `!` زرد — مشکوک ولی لزوماً غلط نیست
- `–` خاکستری — اجرا نشد (مثلاً مجوز نبود)

آخر کار یک خلاصه با فهرست باگ‌های تأییدشده چاپ می‌شود.
کد خروج ۱ یعنی حداقل یک باگ پیدا شد — پس در CI هم قابل استفاده است.

## اگر پچ را هنوز اعمال نکرده‌اید

روی نسخه‌ی فعلی سایت انتظار داشته باشید این‌ها قرمز شوند:

- `POST /auth/refresh` بدون کوکی → ۵۰۰ می‌دهد به‌جای ۴۰۱
- ورودی‌های بی‌معنا (اولویت، جریان کاری، نقش) پذیرفته می‌شوند
- مالک ناموجود → ۵۰۰ به‌جای ۴۲۲
- بازبینی اجباری از راه `IN_QA` دور زده می‌شود
- تغییر رمز، نشست خود کاربر را هم می‌کشد
- پاک کردن مهلت در دفتر ثبت می‌شود ولی اعمال نمی‌شود
- مدیر می‌تواند حساب خودش را غیرفعال کند

بعد از اعمال فایل‌های این بسته، همه‌ی این‌ها باید سبز شوند. همین اسکریپت
راه سنجش کار من است — قبل و بعد اجرا کنید و مقایسه کنید.
