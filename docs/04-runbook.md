# سند ۰۴ — Runbook عملیاتی

راهنمای اجرا، بکاپ، بازیابی و رفع مشکل برای صاحب پروژه. برای اجرای هر بند نیازی به دانش فنی عمیق نیست.

---

## ۱) اولین اجرا

```bash
cp .env.example .env
```

در `.env` این سه مقدار را حتماً عوض کنید: `ADMIN_EMAIL`، `ADMIN_PASSWORD`، و هر دو مقدار `JWT_*`.

```bash
npm install
npm run db:migrate
npm run db:seed
npm run build
npm start
```

اپ روی پورت ۳۰۰۰ بالا می‌آید. با ادمین وارد شوید، رمز را عوض کنید، و بلافاصله **مدیر دوم** بسازید.

> در محیط production اگر رمز ادمین همان مقدار پیش‌فرض باشد، اپ عمداً بالا نمی‌آید.

## ۲) بکاپ

بکاپ روزانه خودکار است و ۱۴ نسخه آخر نگه داشته می‌شود. برای گرفتن دستی:

```bash
npm run backup:now
```

خروجی در `data/backups/` قرار می‌گیرد: یک فایل `app-<زمان>.db` و یک آرشیو `uploads-<زمان>.tar.gz`.

بکاپ با `VACUUM INTO` گرفته می‌شود، یعنی حین کار کردن اپ هم امن است.

## ۳) بازیابی

```bash
npm run backup:restore                      # فهرست نسخه‌های موجود
npm run backup:restore -- --file=app-2026-08-29T10-00-00-000Z.db
```

نسخه فعلی قبل از بازنویسی خودکار کنار گذاشته می‌شود. بعد از بازیابی اپ را ری‌استارت کنید.

> **قبل از شروع پایلوت این کار را یک بار واقعاً انجام دهید.** بکاپی که تست نشده، بکاپ نیست.

## ۴) بازنشانی رمز

از داخل UI: بخش مدیریت، دکمه بازنشانی رمز کاربر. رمز موقت نمایش داده می‌شود.

اگر خود ادمین قفل شد، از ترمینال سرور:

```bash
npm run admin:reset-password -- --email=admin@example.com
```

## ۵) انتقال به سرور شرکت

```bash
git clone <repo> && cd pe-os
npm install && npm run build
# پوشه data/ را از ماشین قبلی کپی کنید
npm start
```

هیچ دیتابیس یا سرویس خارجی لازم نیست. فقط `data/` باید منتقل شود.

## ۶) حذف کامل پایلوت

بکاپ بگیرید، `data/` را کپی کنید، سپس رانتایم و ریپو را حذف کنید. هیچ سرویس بیرونی باقی نمی‌ماند.

---

## رفع مشکل

| نشانه | علت محتمل | کار |
|---|---|---|
| اپ بالا نمی‌آید و از رمز پیش‌فرض می‌گوید | `ADMIN_PASSWORD` عوض نشده | مقدار `.env` را تغییر دهید |
| خطای `SQLITE_BUSY` | نوشتن هم‌زمان سنگین | بررسی کنید فقط **یک** اینستنس اجرا باشد |
| بعد از ری‌استارت داده‌ها رفته‌اند | دیسک پایدار نیست | میزبانی را عوض کنید؛ `data/` باید باقی بماند |
| تاریخ‌ها یک روز جابه‌جا نشان داده می‌شوند | `TZ` تنظیم نشده | `TZ=Asia/Tehran` در `.env` |
| `/api/v1/health` وضعیت `degraded` می‌دهد | دیسک پر یا فقط‌خواندنی | فضای دیسک را بررسی کنید |
| بورد خالی است ولی کار وجود دارد | فیلتر فعال مانده | فیلترها را پاک کنید |

## پایش روزانه

یک بار در روز `/api/v1/health` را چک کنید. باید `{"status":"ok"}` برگرداند. اگر `degraded` بود، دیسک اولین چیزی است که باید نگاه کنید.
